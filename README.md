# Домашнє завдання 5. Алгоритми пошуку

Порівняння алгоритмів Боєра–Мура, Кнута–Морріса–Пратта та Рабіна–Карпа для пошуку першого входження підрядка у двох статтях.

## Запуск

У кореневій папці проєкту виконайте команду. Достатньо Python 3 зі стандартною бібліотекою.

```bash
python -X utf8 benchmark.py
```

## Вхідні дані

| Файл | Стаття | Довжина тексту, символів | Наявний підрядок | Індекс першого збігу |
|---|---|---:|---|---:|
| `data/article1.txt` | Використання алгоритмів у бібліотеках мов програмування | 12 655 | `ефективніше застосовувати` | 6348 |
| `data/article2.txt` | Методи та структури даних для реалізації бази даних рекомендаційної системи соціальної мережі | 18 397 | `дискретні структури даних` | 9423 |

У двох файлах використано той самий вигаданий підрядок `пошук у бібліотеці Марса!`. Усі підрядки мають довжину 25 символів. Наявні входження починаються приблизно посередині кожного тексту. Індекси рахуються з нуля, а для відсутнього підрядка функції повертають `-1`.

## Методика

Для кожної комбінації алгоритму, статті й підрядка `timeit.repeat` виконав 7 серій по 100 викликів. Медіану часу серій поділено на 100 і переведено в мікросекунди. У час виклику входять підготовка шаблону та пошук. Читання файлів, перевірка індексів через `str.find` і виведення таблиці виконуються поза замірами.

Наведені нижче заміри отримано у CPython 3.12.14 на Windows. Середнє для кожної статті обчислено за двома сценаріями з однаковою вагою. Загальне середнє обчислено за всіма чотирма сценаріями. Для середніх використано значення до округлення.

## Результати

Час одного виклику в мікросекундах. Жирним виділено найменший час у кожному рядку.

## Висновки

- У першій статті Боєр–Мур був найшвидшим в обох сценаріях із середнім часом 152,23 мкс. У другій статті він також переміг в обох сценаріях із середнім часом 242,85 мкс.
- За всіма чотирма сценаріями Боєр–Мур мав найменший середній час. Кнут–Морріс–Пратт витратив у середньому приблизно в 4,1 раза більше часу, а Рабін–Карп — у 12,8 раза більше.
- Боєр–Мур може пропускати кілька позицій за раз завдяки правилам поганого символу та доброго суфікса. Кнут–Морріс–Пратт послідовно читає символи тексту, використовуючи префіксну таблицю для відновлення часткового збігу. У цій реалізації Рабін–Карп оновлює хеш на кожному зсуві вікна на один символ.
- Пошук вигаданого підрядка тривав довше в усіх трьох алгоритмах. Наявний підрядок дозволяв завершити пошук приблизно посередині тексту, а для вигаданого треба було пройти до останньої можливої позиції. Порівняння стосується цих текстів, підрядків і реалізацій Python.
